# OrangeFox для Pixel на Tensor - `device/google/pixels`

**[English](README.md)** | [Русская версия](README_ru.md)

`Гайд v3 · 2026-10-26 · R12 / AIO universal`

Один установщик на **все Pixel на Tensor** - от Pixel 6 до 11, фолды и планшет (25 устройств, 6 семейств SoC). Модель определяется в рантайме, стоковое ядро сохраняется всегда, поставляется только рамдиск рекавери. Рекавери живёт только в `vendor_boot`.

<details>
<summary>⚠️ Важно знать перед установкой</summary>

- Это **рекавери**, а не прошивка: мини-система для установки zip, бэкапов, форматирования. Android оно не заменяет.
- Для установки нужен **разблокированный bootloader - а это вайп телефона** (фото, чаты, файлы). Сначала бэкап.
- **Не начинайте, если:** это единственный телефон и он нужен завтра; командную строку ПК видите впервые. Сложность: **средняя**. Время: ~10 мин. Первая загрузка в рекавери идёт чуть дольше обычной - дождись главного экрана.
- 100% гарантия запуска - только на `shiba` (повседневный девайс мейнтейнера: каждая сборка сначала грузится там, и только потом едет дальше). Ячейки других семейств ниже - полевые и тестерские результаты: зелёным отмечено то, что подтверждено на реальном железе, а не угадано. Если ты тут впервые - начни с [гайда тестеру](docs/tester-guide_ru.md).

</details>

<details>
<summary>🔥 Зачем эта сборка</summary>

- **AIO universal** - один `*-aio.zip` на все устройства; перепутать образ под модель не выйдет.
- **Стоковое ядро сохраняется** - нет kernel-профилей и правок cmdline. Раскладка `vendor_boot`, first-stage, dlkm остаются стоковыми; меняется только часть рекавери.
- **Расшифровка data** - FBE-метаданные через Trusty TEE KeyMint из исходников (без пребилдов), weaver Titan M2/M3 (M2 на Pixel 6-9, M3 на 10/11), мультидевайс zoned+exp.
- **Тач, который выживает** - модули сначала ищутся в твоём стоковом `vendor_dlkm`, а если `super` битый и оттуда ничего не прочитать - подхватывается архив, который положил установщик (`modules/<device>.lgz`). Поэтому даже с убитым `super` тач работает (проверено вживую на G3: сток не читается на обоих слотах, а 12/12 модулей встают).
- **Защита от дурака в USB** - сверка патча ядра с прошивкой до любого переключения VBUS. Патчи не сошлись - остаёмся в обычном девайс-режиме (adb цел), вместо паники.
- **Быстрая прошивка + логи** - опциональная скоростная установка ROM (локально ~1 мин против ~4 стока, sideload тоже умеет), живое переключение слота (цепочка ROM → GApps → Magisk шьётся за один заход без ребута), пачка логов одной командой `flog.sh`.

</details>

## Установка - основной путь (тип A, AIO zip)

<details>
<summary>☑️ Перед стартом</summary>

- Bootloader **разблокирован**. Батарея 50%+, родной кабель, при глюках fastboot - порт USB 2.0.
- **Zip сначала РАСПАКОВАТЬ** (установка с ПК): нужны живые файлы - `install-desktop.sh` / `install-desktop.bat`, `export.txt`, `bin/`, один `*.ramdisk.lz4`. Запуск из окна архиватора не работает никогда.
- **Проверьте MD5** до прошивки: Linux `md5sum file`, Windows `certutil -hashfile file MD5`. Хеш не совпал - файл битый: качайте заново и ничего не репортьте.
- Первый раз на Windows: поставьте **Google USB driver**, иначе fastboot телефон не увидит.

</details>

1. Телефон в режиме **bootloader** (Громкость вниз + Power), кабель в ПК.
2. Запустите установщик: Linux `./install-desktop.sh`, Windows `install-desktop.bat` (или двойной клик по AppImage / `.exe`).
3. Он заберёт ваш стоковый `vendor_boot`, заменит **только часть рекавери**, пересоберёт **оба слота**, проверит прошивку побайтово. Успех = `RESULT: OK`. Установщик спросит раскладку: **тип A** (классика, проверена - всем кроме Pixel 6 брать его), **тип B** (всё в platform), **тип C** (только пейлоад в platform). B и C - эксперименты; тестерам Pixel 6 гонять все три по кругу (стоковый `vendor_boot` → установка → репорт: грузится рекавери? грузится система? → по новой), потому что обычная загрузка там сломана и раскладки - кандидаты в фикс.
4. **Сразу** перезагрузка в рекавери (`fastboot reboot recovery`), в систему пока не грузиться. Первая загрузка идёт чуть дольше обычной - дождись главного экрана.
5. Готово - OrangeFox в `vendor_boot` на обоих слотах, стоковые ядро/first-stage целы. Бэкап + `install.log` - в `backup/<дата-время>/` рядом со скриптом.

Как установщик выбирает файлы: коднейм определяется сам (`ro.product.device`, запасной - `ro.build.product`; сверяется с пулом Pixel внутри бинаря). Нужный архив с тач-модулями `modules/<device>.lgz` подкладывается в корень пейлоада (`--inject-lgz`). KeyMint HAL и VINTF-манифест под твою семью остаются, остальные удаляются, `ro.recovery.keymint` прописывается. Адрес USB-контроллера подставляется в rc-файлы. Из двух сборок установщика предпочитается small, архитектура определяется сама. Раскладку можно переопределить через `RECOVERY_IS_PLATFORM=` в `export.txt`: пусто - классический тип A, `var1` - всё в platform, `var2` - только пейлоад в platform.

> **На стоке + Windows? Делайте этот путь, остальное не смотрите.** Способы ниже требуют рут / рекавери / второй телефон, которых пока нет.

<details>
<summary>📦 Другие способы поставить тот же zip (всего 5)</summary>

- **Magisk / KernelSU / APatch** - прошейте zip в менеджере как модуль. Это **не** модуль: установка постоянная, после себя удаляется.
- **Любое рекавери (OFox / TWRP / Lineage)** - Install → выбрать zip → свайп. В Lineage recovery: ADB Sideload → `adb sideload file.zip`.
- **ADB sideload** - в рекавери Advanced → ADB Sideload, затем на ПК `adb sideload file.zip`.
- **Termux (телефон-в-телефон по OTG)** - цель по USB-OTG, как Linux (`./install-desktop.sh`), но сначала `pkg install android-tools`.
- **Терминал / adb shell (рут уже есть)** - если в загруженной системе уже есть рут.
- ARM64 ПК / Termux: встроенные tools только x64 - поставьте platform-tools системно заранее. 32-бит не поддерживается.

</details>

## Прошивка ROM - скоростная + живое переключение слота (в рекавери)

- **Скоростная прошивка** (по умолчанию выкл): zip прошивки ставится ~за минуту - полевые замеры локально 0:50 против 3:50 стока, sideload 3:05 против 8:30 стока (zip 3.3 ГБ, shiba). Тумблер на странице подтверждения прошивки, а для sideload-установок - на экране sideload. На шифрованных девайсах тоже работает. Подробности → [док движка](docs/recovery-engine_ru.md).
- **Живое переключение слота** (по умолчанию выкл): без ребута между прошивкой и аддонами - цепочка **ROM → GApps → Magisk** шьётся за один заход. Подробности → [док движка](docs/recovery-engine_ru.md).

## Обновление / переустановка - изнутри рекавери

- ПК не нужен: оба слота `vendor_boot` пересобираются из **своего же стокового образа** (заголовок, cmdline, dtb - из самого слота, ничего не штампуется).
- Бэкапы лежат в `/sdcard/backup_vendor_boot/` (+ `install.log`). **Скопируйте бэкап с телефона ДО Format Data прошивки** - формат трёт и `/sdcard`. Сначала `adb pull` на ПК.
- Восстановление: установщик → Restore → выбрать бэкап. Шьётся как есть.

<details>
<summary>🔍 Сноски - битый super, USB-защита, тестеры</summary>

- **Битый `super`:** тач работает, потому что модули берутся из архива, который установщик заранее положил в пейлоад (проверено вживую на G3: сток падает на обоих слотах, 12/12 модулей грузятся). Вибрации нет - прошивка вибро лежит на `vendor` внутри `super`, а его уже не прочитать.
- **Защита от дурака в USB:** ядро новее прошивочных модулей вешает девайс, когда кастомный OTG-стек принудительно переключает питание VBUS в хост (видели в поле). Перед любой загрузкой шима или записью питания рекавери сверяет патч запущенного ядра с `vermagic` прошивочных модулей (смотрит в основном стоковые `.ko`; свои шимы в сравнение не берёт). Если патчи не сошлись - весь кастомный стек остаётся выключенным (нет сервисов, нет переключения VBUS - только девайс-режим, adb цел), вместо паники. Монолитные ядра проверку пропускают; деревья без читаемых стоковых модулей идут дальше, но с явным варнингом в логе.
- Тестеры не очень активны, поэтому мелкие посемейные фиксы отложены - текущее состояние достаточно стабильно для первого релиза.

</details>

<details>
<summary>❓ Вопрос → ответ</summary>

- **Какой файл шить?** → Установщик `*-aio.zip` вашей сборки. По-девайсных образов не существует.
- **Распаковывать или нет?** → Установка с ПК: **распаковать**. Менеджер / рекавери: шить `.zip` **как есть**.
- **MD5 не сошёлся?** → Битый файл. Качайте заново, не шейте. Telegram иногда режет `.img` - сверяйтесь с опубликованным хешем.
- **Какой слот?** → Никакой: установщик шьёт оба слота сам, выбирать не нужно.
- **Бэкап скопировать ДО Format Data?** → Да. Формат трёт и `/sdcard/backup_vendor_boot/`. Сначала `adb pull` на ПК.
- **Бутлуп / завис?** → В рекавери `flog.sh` (или `adb shell flog.sh`), приложите один `fox_logs_<device>_<family>_<stamp>.tar.gz` + модель. Без логов чинить нечего - репорт без архива рассматривать не будут.
- **Нет adb на экране пароля (Stable)?** → Так задумано: Stable гасит `adbd` + MTP при загрузке ради безопасности; стартуют при первом входе на главную. Нужен adb для отладки → берите Beta-сборку.
- **Нет тача?** → Смотрите `/tmp/recovery.log`: строки `ko-fetch`, `lsmod` на ваши `touch_modules`, пропуски depth-guard. Шлите `flog.sh`.
- **Не расшифровывает?** → Статус сервисов KeyMint/weaver, слот `.weaver`, `ro.crypto.fs_crypto_blkdev` в логах. C++ HAL на zuma уходит в цикл (не совпал с TA) - рабочий вариант только Rust из исходников.
- **Нет USB/OTG-хоста?** → Пути VBUS, `patch_dwc3`, бинд UDC в логе `otg-auto`. Если сработал USB-guard (ядро новее прошивки) - только девайс-режим, adb цел.
- **Format Data падает?** → Строки `FoxFstab` / `FoxTeardown` / `FoxFormat` в `/tmp/recovery.log` → [диагностика](docs/diagnostics_ru.md). `EBUSY` = что-то держит `/data`: чисто перезагрузите рекавери и повторите.
- **Назад в сток + relock?** → Прошейте заводские образы, затем `fastboot flashing lock`. Лочить только на 100% стоке, иначе кирпич.
- **Куда репортить?** → в чат своей семьи, чтобы логи не мешались (новости: [@OFRPforTensor](https://t.me/OFRPforTensor)):
  G1 Pixel 6 ([чат](https://t.me/OFRP_tensor_g1)) · G2 Pixel 7 ([чат](https://t.me/OFRP_tensor_g2)) · G3 Pixel 8 ([чат](https://t.me/OFRP_tensor_g3)) ·
  G4 Pixel 9 ([чат](https://t.me/OFRP_tensor_g4)) · G5 Pixel 10 ([чат](https://t.me/OFRP_tensor_g5)) · G6 Pixel 11 ([чат](https://t.me/OFRP_tensor_g6)).

</details>

<details>
<summary>📖 Термины (коротко)</summary>

- **`vendor_boot`** - раздел, где на всех Tensor Pixel живёт рекавери. `boot` / `dtbo` / `init_boot` ради рекавери шить не надо.
- **Слоты A/B** - две копии системы; обновление едет в свободную. Установщик пишет обе.
- **AIO zip** - универсальный установщик: определяет модель в рантайме, меняет только фрагмент рекавери.
- **Bootloader** - запускает телефон до Android. Разблокировка трёт все данные.
- **Sideload** - отправка zip с ПК (`adb sideload`) в рекавери.
- **Расшифровка FBE** - разблокировка файлового шифрования через Trusty TEE KeyMint + weaver Титана.
- **KeyMint (cpp / rust)** - C++ HAL под старый TA (G1/G2) vs Rust HAL под новый TA (G3-G6). Едут оба; чужой тихо выходит.
- **LGZ-кластер** - упакованный рамдиск, который стаб распаковывает до настоящего init.
- **Стаб (PID 1)** - статическая замена `init`, распаковывает LGZ и запускает настоящий `fox.init`.
- **`flog.sh`** - одна команда в рекавери, пакует все логи в один архив для багрепорта.
- **Format Data vs wipe** - формат трёт всё включая фото (крипто-стирание: ключи в `/metadata` + Титан); wipe хранит медиа.
- **MD5** - отпечаток файла. Не совпал с опубликованным - загрузка битая.

</details>

**Три принципа, на которых всё держится:**

1. **Конфиг вместо кода.** Вендор-специфика (модули тача, sysfs-пути, пропсы, cmdline ядра) живёт в JSON (`families/*/family.json`, `devices/*/pixel.json`), а не в `.mk` и не в рантайм-коде.
2. **Сборка из исходников.** KeyMint HAL, weaver-демон, boot-движок - всё компилируется из `include/` и `patches/`. Пребилдов нет; сток нужен только как референс cmdline и fstab.
3. **Три копии всегда синхронны.** Каждый патч на чужой код хранится как тройка `original` / `modified` / `.patch`, живое дерево приведено к снапшоту.

**Быстрый старт:**

```bash
./build.sh --list                  # дерево семейств и девайсов
./build.sh -n test8 --build-type Beta   # универсальный пейлоад + installer zip
```

> Если вы AI-модель и исследуете проект: `build.sh` не запускать (сборка - прерогатива человека, границы вашей зоны - в [`docs/build-system_ru.md`](docs/build-system_ru.md)); `test*` не коммитить; `docs/` коммитить; каждый патч - тройкой `original` / `modified` / `.patch`.
>
> Если вы AI-модель и **меняете** логику дерева (код, конфиги, скрипты, флаги, поведение сборки) - зафиксируйте изменение во всех readme, которых оно касается: обновите соответствующий `docs/*_ru.md` **и** его английский двойник `docs/*.md`, а если меняется карта разделов - и таблицу выше.
