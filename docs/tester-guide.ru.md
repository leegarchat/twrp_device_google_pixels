# Тестирование тестовых сборок OrangeFox — полный гайд (RU)

Этот гайд — для тестеров **экспериментальных (тестовых) сборок OrangeFox**.
Тестовая сборка может не загрузиться, сломать расшифровку или оставить слот
незагружаемым — действуй строго по гайду, и путь назад будет всегда.

## 0. Подготовка

- ПК с установленными `platform-tools` (`fastboot`, `adb`), проверь что работают.
- USB-кабель + желательно порт/хаб USB 2.0 (меньше отвалов соединения).
- Заряд телефона **> 50%**.
- **Родные factory images** именно под твой девайс (от твоей прошивки), скачаны и распакованы
  (как минимум нужен родной `vendor_boot.img` под твой слот).
- Знай коднейм девайса (`shiba`, `comet`, `grizzly`, …) и текущий слот:
  ```
  fastboot getvar current-slot
  ```
- Сделай бэкап важного. На тестовых сборках **Format Data — только по просьбе**.
- **Сверь хэш образа ДО прошивки.** Telegram иногда отдаёт `.img`
  обрезанными (реальный случай с тестов R11 — из-за этого впустую
  потратили дни на отладку). К каждой тестовой сборке мейнтейнер
  прикладывает `md5` (или он закреплён в https://t.me/OFRPforTensor) —
  сравни:
  ```
  md5sum OrangeFox-test-xxx.img
  ```
  (Windows: `certutil -hashfile OrangeFox-test-xxx.img MD5`.) Не сошлось —
  перекачай, лучше из папки на GDrive по ссылке из канала. **Бутлуп +
  пустой pstore при несовпавшем хэше = битый download, а не баг —
  не репортить, сначала перекачать.**

## 1. Прошивка тестовой сборки

Мейнтейнер скажет, **какой файл и в какой слот** шить. Путь по умолчанию
для всех актуальных сборок — **AIO-пакет установки** ниже. Ручные
fastboot-процедуры — это legacy (до-AIO), они под спойлером в конце
раздела — используй их только когда мейнтейнер прямо сказал.

### AIO-пакет установки (рекомендуется)

Для AIO-тестов мейнтейнер отдаёт инсталлер-пакет вместо сырого `.img`:
пейлоад recovery (`OrangeFox-*-aio.ramdisk.lz4`), `export.txt`, бинарники
инсталлера и platform-tools в комплекте. Это умная замена — стоковый
`vendor_boot` забирается с девайса, подменяется только recovery-фрагмент,
оба слота пересобираются + побайтово проверяются, а датированный бэкап
сохраняется (`backup/` на ПК, `/sdcard/backup_vendor_boot/` на девайсе).
First_stage, cmdline ядра и dlkm всегда остаются стоковыми.

Выбери один вариант (установка везде одинаковая):

1. **ПК / Linux** — загрузи телефон в бутлоадер (классический fastboot,
   НЕ fastbootd), затем:
   ```
   ./install-desktop.sh
   ```
   (или двойной клик по `install-desktop.AppImage`). Меню на стрелках,
   бэкап в `backup/<дата-время>/`, в конце предложение ребутнуться в
   recovery.
2. **ПК / Windows** — то же самое, из бутлоадера:
   ```
   install-desktop.bat
   ```
3. **Magisk / KernelSU (из загруженной системы)** — прошей
   `*OrangeFoxTensorUniversal.zip` в приложении Magisk или KernelSU как
   модуль. Поставится с рутом, бэкап останется на userdata, затем модуль
   сам себя удалит (только установщик, ничего постоянно не ставится).
4. **Из recovery** — прошей тот же zip через Install в любом recovery
   (TWRP/OrangeFox). Прогресс виден на консоли recovery.

Настройки — в `export.txt` рядом с инсталлером:
`SLOT=both|a|b|current`, `MIN_FREE_MB=7` (строго — вместо прошивки в
переполненный раздел установка прервётся). Логи:
`backup/<дата-время>/install.log` (ПК) или
`/tmp/recovery_install/install.log` (на девайсе).

Ручную прошивку `fastboot flash vendor_boot_X` из legacy-спойлера ниже
используй только когда мейнтейнер прямо сказал.

<details>
<summary>Legacy: ручная прошивка через fastboot (только до-AIO сборки — нажми чтобы развернуть)</summary>

Процедура по умолчанию (пример — слот A):

```
fastboot flash vendor_boot_a OrangeFox-test-xxx.img
fastboot reboot recovery
```

#### Pixel 6 series (gs101: oriole/raven/bluejay) — особая процедура

> ⚠️ ТОЛЬКО ДЛЯ ДО-AIO СБОРОК (напр. `test_1-gs101`). Для `-aio` сборок
> НИКОГДА не шей сырой cpio через fastboot — образ семейно-нейтральный,
> ему нужен своп инсталлера (USB-контроллер, fstab, keymint-манифесты),
> иначе на gs101 загрузится. Используй AIO-пакет выше; сырой AIO на
> Pixel 6 грузится с мёртвым USB (нет adb) и кривой геометрией экрана.

У Pixel 6 нет раздела `vendor_kernel_boot`, поэтому шьётся **НЕ**
`.img`, а **рамдиск** `.ramdisk.lz4` в platform-фрагмент (обрати
внимание на висячее двоеточие = пустое имя фрагмента):

```
fastboot flash vendor_boot_a: OrangeFox-test-xxx-gs101.ramdisk.lz4
fastboot reboot recovery
```

(`:default` или `:recovery` здесь НЕПРАВИЛЬНО — первое схлопывает всю
таблицу и убивает стоковый dlkm, второе пишет не в тот фрагмент.)

</details>

Сначала бэкап (бутлоадер, рут не нужен) — оба слота:
```
fastboot fetch vendor_boot_a ./vendor_boot_a.stock.img
fastboot fetch vendor_boot_b ./vendor_boot_b.stock.img
```
Размер должен быть 67108864 байта (64 МБ). Откат:
```
fastboot flash vendor_boot_a vendor_boot_a.stock.img   # или _b
```

Правила:

1. Шей **только** тот раздел, который сказали (обычно `vendor_boot_X`).
   Никогда не шей `super`, `boot`, `system`, `modem`, bootloader или radio
   из тестового пакета без прямого указания.
2. Узнай активный слот **до** прошивки. Если сомневаешься — шей только
   активный слот, второй останется заведомо рабочим запасным.
3. Держи родной `vendor_boot.img` под рукой для мгновенного отката:
   ```
   fastboot flash vendor_boot_a stock_vendor_boot.img   # или _b (родной, от прошивки)
   fastboot reboot
   ```

## 2. Первая загрузка — чек-лист на 60 секунд

После `fastboot reboot recovery` подожди до 60 секунд (USB-стек и сервисы
расшифровки стартуют с задержкой), затем выполни:

> **Важно про adb на экране пароля (тестовые non-Stable сборки).** Ты получил
> тестовую сборку НЕ-Stable (Beta) — в ней нет принудительного отключения
> adb/MTP, которое есть в Stable-сборках. Поэтому adb на экране
> первоначального ввода PIN **может работать, а может нет — разработчик
> точно не знает**: его собственный девайс сейчас без шифрования, и
> проверить этот путь ему не на чем. Твоя задача — зафиксировать факт.
> - Если `adb devices` видит девайс прямо на экране пароля — отлично,
>   выполняй все команды ниже сразу там и напиши в отчёте, что adb на
>   пароле **был**.
> - Если `no devices` — для теста это тоже нормально: уйди с экрана пароля
>   (введи PIN, если тач работает, либо кнопка **Skip** / клавиша «назад»
>   в главное меню без расшифровки — на части сборок её может не быть,
>   тогда только PIN) и выполняй команды после. В отчёте напиши, что adb
>   на пароле **не было**.
> Логи (`recovery.log`, `weaver.log`) пишутся с самого старта в обоих
> случаях — забираются позже целиком, ничего не теряется.

```
adb devices -l
adb shell 'getprop sys.usb.config; getprop init.svc.vendor.keymint.rust-trusty; getprop init.svc.vendor.keymint-trusty; uname -r; getprop ro.boot.slot_suffix'
```

Признаки здоровья:

| Проверка | Норма |
|---|---|
| `adb devices` | девайс виден как `recovery` |
| `sys.usb.config` | `mtp,adb` |
| keymint-сервис | `running` (ровно один из rust-trusty / trusty) |
| `uname -r` | ядро, под которое собрано (если неясно — спроси) |
| суффикс слота | тот слот, куда шил (`_a` / `_b`) |

Дальше сними логи — [см. §3](#3-снятие-логов--сначала-flogsh), сначала
`flog.sh`. Одна команда заменяет все ручные пуллы ниже.

## 3. Снятие логов — сначала flog.sh

`flog.sh` едет внутри каждой свежей тестовой сборки. Одна команда собирает
весь отчётный комплект — **предпочтительнее ручных `adb pull`**: забирает
строго больше (ранние AIO-логи, пропсы, подсветка, pstore, логи установщика)
и выставляет читаемые права, чтобы файлы открывались по MTP/с ПК.

Запускается из recovery — по adb **или** из терминала Fox
(Advanced → Terminal — adb вообще не нужен):

```
adb shell flog.sh
```

В конце — путь к комплекту (запомни метку времени):

```
flog: DONE -> /data/media/0/fox_logs/20260920_110538
```

### 3.1. Куда ложится комплект — матрица userdata

| Состояние userdata | Назначение | Как забрать на ПК |
|---|---|---|
| Расшифрована + writable (PIN введён, или шифрования нет) | `/data/media/0/fox_logs/<метка>/` — **переживает перезагрузку** | `adb pull /data/media/0/fox_logs/<метка>` в любой момент позже (даже из загруженной системы) или скопировать по MTP |
| Залочена / unwritable | `/tmp/fox_logs/<метка>/` — RAM, **умирает при перезагрузке** | `adb pull` **немедленно**, пока сидишь в recovery |

### 3.2. Что входит в комплект

| Файл | Источник | Что доказывает |
|---|---|---|
| `recovery.log`, `weaver.log` | `/tmp/*.log` | поток recovery + расшифровки |
| `reflash_twrp.log`, `install-*.log` | установка на девайсе | путь reflash/install (если использовался) |
| `aio_stub.log`, `aio_runatinit.log` | стаб + Rust early-boot | детект семейства, своп, USB-rescue |
| `dmesg.log`, `logcat.log` | ядро + система | тач/экран/USB/расшифровка на уровне железа |
| `props.txt` | `getprop` + ключевые пропсы | слот, семейство, сервисы, состояние USB |
| `backlight.txt` | sysfs подсветки | проблемы экрана (значения в момент поломки) |
| `pstore*` | `/sys/fs/pstore/` | краши ядра (переживают перезагрузку) |
| `families.txt`, `pixelrunatboot.json` | конфиг установщика | какой пейлоад/слот-политика дали этот бут |

Строки `- missing:` в выводе `flog.sh` — тоже ответ: отсутствующий
`aio_stub.log`, например, говорит разработчику, что стаб не логгировал.
Не вырезай их; вывод консоли тоже присылай.

### 3.3. Нет adb вообще (мёртвый USB)?

1. Терминал Fox → `flog.sh` → комплект ляжет на userdata, если расшифрована.
2. Перезагрузись в систему, забери по `adb` или скопируй по MTP.
3. Если userdata тоже залочена — фотографируй ключевые экраны и иди к
   [исходам B/C](#6-исходы-ad).

### 3.4. Ручной fallback (сборки без flog.sh)

```
adb pull /tmp/recovery.log
adb pull /tmp/weaver.log
adb shell 'dmesg > /tmp/dmesg.log; logcat -d -v time > /tmp/logcat.log'
adb pull /tmp/dmesg.log
adb pull /tmp/logcat.log
```

Для любого хардверного разбора (тач, экран, USB, расшифровка, сенсоры)
`dmesg`/`logcat` — самые важные файлы после самого `recovery.log`,
всегда целиком, никаких выдержек.

## 4. Тест расшифровки

1. Если просит PIN/пароль/паттерн — введи.
2. Успех = видны файлы (Internal Storage), а в `recovery.log` есть
   `User 0 Decrypted`.
3. Не работает тач — это **НЕ провал теста**, если не сказано обратное.
   Сообщи и продолжай через `adb`.
4. Пришли: комплект `flog.sh` ([§3](#3-снятие-логов--сначала-flogsh))
   и видно ли `/data/media`.

## 5. Как отрисовывается UI (особенно фолды и планшеты!)

На девайсах с новой display-логикой (фолды, планшеты) это отдельный пункт
отчёта — смотри внимательно и фиксируй:

1. **Какой экран показывает UI** (фолд: внешний/cover или внутренний?
   В каком состоянии был девайс при загрузке — сложен или раскрыт?).
2. **Есть ли чёрные полосы** по краям и с каких сторон (слева/справа,
   сверху/снизу, со всех четырёх). Полосы — штатный letterbox-режим,
   их наличие/отсутствие и симметрия важны.
3. **Растянутость**: круги выглядят кругами или эллипсами? Текст и иконки
   в том же масштабе, что рамки, или «плывут»? Клавиатура на всю ширину
   или уже экрана?
4. **Поворот**: UI прямо или повёрнут на 90°? (На внутреннем экране фолда
   возможен доворот — сообщи какой.)
5. **Соответствие тача экрану**: тап попадает туда, куда показывают?
   (На фолде отдельно: тач внешнего экрана работает на внешнем, а не
   наоборот.)
6. **Сфотографируй экран** на телефон — фото информативнее любых слов.
   Для фолда: фото сложенным + раскрытым.

Если adb доступен — добавь к отчёту:
```
adb shell 'getprop DOF_SCREEN_W; getprop DOF_SCREEN_H; getprop DOF_PROGRESSIVE_SCALE'
```

### 5.1. Тесты функций (только если просили)

- **Тач**: работает / частично / мёртв + `dmesg | grep -i touch`.
- **Фонарик / вибро**: работает или нет.
- **OTG / USB-мышь**: работает или нет.
- **Format Data / Reflash Recovery**: **ЗАПРЕЩЕНЫ на тестовых сборках**,
  пока мейнтейнер явно не разрешил (некоторые билды отказываются сами —
  текст отказа тоже присылай, он подтверждает работу защиты).

## 6. Исходы A–D

### Исход A — грузится, adb есть

Выполни разделы 2–5 и отправь отчёт ([см. §7](#7-шаблон-отчёта-копипаст)).
Всё.

### Исход B — грузится, но НЕТ adb

1. Подожди полные 60 с, переткни кабель, попробуй другой порт / USB 2.0-хаб.
2. Затем сними логи без adb: терминал Fox → `flog.sh`
   ([§3.3](#33-нет-adb-вообще-мёртвый-usb)).
3. Проверь fastbootd: `fastboot devices`. Если девайс виден в fastbootd —
   ядро живо, проблема в USB-gadget — так и сообщи.
4. Если полная тишина — переходи к исходу C (откат).

### Исход C — НЕ грузится (логотип / чёрный экран / бутлуп)

**Не паникуй. Не шей что попало.** Откатывайся:

1. Прошей **родной (заведомо рабочий)** `vendor_boot.img` в **тот же слот**, куда шил тест:
   ```
   fastboot flash vendor_boot_a stock_vendor_boot.img   # или _b (родной, от прошивки)
   ```
2. Загрузись в систему как обычно.
3. С рутом сними дампы краша ядра **до того, как их затрут** (вторая
   перезагрузка может их ротировать — будь быстрым, одна загрузка):
   ```
   su
   ls /sys/fs/pstore/
   cat /sys/fs/pstore/console-ramoops-0 > /sdcard/ramoops_console.txt
   cat /sys/fs/pstore/dmesg-ramoops-0  > /sdcard/ramoops_dmesg.txt
   dmesg > /sdcard/dmesg_boot.txt
   getprop ro.boot.slot_suffix; uname -r
   ```
4. Стяни файлы на ПК (`adb pull /sdcard/ramoops_console.txt` …) и пришли
   **все** + какой файл шился и в какой слот.

#### Хитрость boot → crash → смена слота / загрузка в систему

- Если слот B с тестовой сборкой ушёл в бутлуп, загрузчик может сам пометить
  его незагружаемым и откатиться на слот A — проверь после падения:
  `fastboot getvar current-slot`.
- Можно форсировать другой слот вручную: `fastboot --set-active=a` (или `b`),
  затем загрузиться в систему и снять pstore-дампы как выше.
- Главное: **pstore переживает перезагрузку, но не бесконечные** — снимай
  дампы на ПЕРВОЙ удачной загрузке после краша, не перезагружайся дважды.

### Исход D — грузится с adb, но расшифровка НЕ работает

Пришли комплект `flog.sh` ([§3](#3-снятие-логов--сначала-flogsh)) плюс:

1. Вывод ручного запуска HAL (погоняй ~15 секунд, затем Ctrl-C):
   ```
   adb shell '/vendor/bin/hw/android.hardware.security.keymint-service.rust.trusty --dev /dev/trusty-ipc-dev0'
   ```
   (Если в сборке C++ HAL — мейнтейнер даст другой путь.)
2. Состояния сервисов:
   ```
   adb shell 'getprop init.svc.recovery_storageproxyd; getprop init.svc.recovery_weaver'
   ```

## 7. Шаблон отчёта (копипаст)

```
Файл сборки : <точное имя файла>
Прошит в    : vendor_boot_a / vendor_boot_b
Девайс      : <коднейм, напр. grizzly>
Исход       : грузится+adb / грузится-без-adb / не грузится / грузится-без-расшифровки
adb виден   : да / нет
adb на пароле: был / не было (если девайс зашифрован)
расшифровка : ок / провал / не пробовал
тач         : ок / мёртв / частично
UI          : полосы (какие стороны) / растянуто / поворот / какой экран (фолд: сложен/раскрыт) + фото
Приложено   : fox_logs/<метка>/ (весь комплект flog.sh: recovery.log, weaver.log,
             dmesg.log, logcat.log, aio_*.log, props.txt, …)
             — или те же файлы, стянутые вручную
             (+ ramoops_console.txt, ramoops_dmesg.txt, dmesg_boot.txt при исходе C)
Заметки     : <всё необычное: сколько грузилось, тексты ошибок, ...>
```

## 8. Золотые правила

1. Одно изменение за раз. Не совмещай тестовую сборку с другими модами.
2. Родные (заведомо рабочие) образы готовы **до** прошивки, а не после.
3. Сначала логи, потом выводы — прикладывай всегда полные файлы.
4. НЕ жми «Reflash Recovery», НЕ делай Format Data, НЕ шей другие разделы
   на тестовых сборках без указания.
5. Что-то повело себя странно — сфотографируй/запиши точный текст.
   «Не работает» — не отчёт.

## 9. Как сдампить родной vendor_boot (бэкап перед тестом)

Если нет factory images под рукой — сдампь заведомо рабочий `vendor_boot`
прямо с девайса **до** прошивки теста. Проще всего — бутлоадер, рут не
нужен (работает и для Pixel 6):
```
fastboot fetch vendor_boot_a ./vendor_boot_a.stock.img
fastboot fetch vendor_boot_b ./vendor_boot_b.stock.img
```

Либо нужен root (в системе) или recovery:

Из системы с рутом (оба слота сразу):
```
su
dd if=/dev/block/by-name/vendor_boot_a of=/sdcard/vendor_boot_a.stock.img bs=4M
dd if=/dev/block/by-name/vendor_boot_b of=/sdcard/vendor_boot_b.stock.img bs=4M
ls -l /sdcard/vendor_boot_*.stock.img
```

Из recovery (adb, root там по умолчанию):
```
adb shell 'dd if=/dev/block/by-name/vendor_boot_a of=/sdcard/vendor_boot_a.stock.img bs=4M'
adb shell 'dd if=/dev/block/by-name/vendor_boot_b of=/sdcard/vendor_boot_b.stock.img bs=4M'
adb pull /sdcard/vendor_boot_a.stock.img
adb pull /sdcard/vendor_boot_b.stock.img
```

Проверка: размер должен быть 67108864 байта (64 МБ). Шей обратно так:
```
fastboot flash vendor_boot_a vendor_boot_a.stock.img   # или _b
```

## 10. Шпаргалка fastboot/adb

```
fastboot getvar current-slot
fastboot --set-active=a|b
fastboot flash vendor_boot_a|b <файл>   # legacy, ручной путь (до-AIO)
fastboot flash vendor_boot_a: <ramdisk.lz4>   # legacy, только Pixel 6 series (двоеточие!)
./install-desktop.sh                              # AIO-инсталлер, Linux (из бутлоадера)
install-desktop.bat                               # AIO-инсталлер, Windows (из бутлоадера)
fastboot fetch vendor_boot_a|b ./backup.img   # бэкап без рута
fastboot reboot recovery
fastboot reboot
adb devices -l
adb shell flog.sh                                 # полный комплект логов (предпочтительно)
adb pull /data/media/0/fox_logs/<метка>          # забрать комплект (userdata)
adb pull /tmp/fox_logs/<метка>                   # забрать комплект (без userdata, срочно)
adb pull /tmp/recovery.log
adb pull /tmp/weaver.log
adb shell 'dmesg > /tmp/dmesg.log; logcat -d -v time > /tmp/logcat.log'
adb pull /tmp/dmesg.log
adb pull /tmp/logcat.log
adb shell 'dmesg | grep -i -E "touch|keymint|trusty|gsc|sg1" | head -30'
```
