# Система сборки (`build.sh`)

`Гайд v3 · 2026-10-26 · один универсальный пейлоад`

Единственная точка входа сборки (только AIO): фиксированная цель `aio`, lunch, `mka`, извлечение cpio, пакование установщика.

<details>
<summary>🤖 Правила для AI-модели, исследующей проект</summary>

- **Не запускайте `build.sh`.** Сборка - прерогатива человека: она долгая, чистит `out/`, упирается в лимит `/tmp` (16 ГБ tmpfs) и требует решений (слоты, теги). Ваш запуск может уничтожить чужие артефакты или зависнуть на интерактиве.
- **Ваша зона:** готовить дерево, писать код/патчи/доки и проверять результат без сборки - `apply_patches.py --check`, `patch --dry-run`, `bash -n`, `build.sh --list`, побайтовые сверки.
- Не чистите `/tmp/pixels/` и `out/`, пока идёт чужая сборка.
- `test*` - в `.gitignore` (тестовые скрипты не коммитить); `docs/` - коммитить.

</details>

## Флаги - сначала happy path

```bash
./build.sh -n test8 --build-type Beta
```

| Флаг | Значение |
|---|---|
| `-n TAG` | Имя в имени пейлоада/установщика; попадает и в версию внутри рекавери (`R12.0_<TAG>[_<patch>]` через `FOX_BUILD_NAME`) |
| `-p N` | Числовой патч к версии внутри рекавери (`R12.0[_<name>]_N`) |
| `--build-type TYPE` | Тип сборки, дефолт `Stable` (подробности ниже) |
| `--list` | Показать дерево семейств/девайсов и выйти (ничего не собирает) |
| `-j N` | Параллелизм сборки (можно `-jN`), дефолт nproc |

<details>
<summary>🧰 Остальные флаги</summary>

| Флаг | Значение |
|---|---|
| `-f aio` | Только для совместимости (можно опускать). Любое другое значение - **ошибка**: посемейных сборок нет |
| `--new-theme` | Собрать переработанную wide-тему (`FOX_REWORK_THEME=1`); по умолчанию стоковая базовая |
| `--push GROUP` | Отправить готовый AIO zip в Telegram-чат(ы) (`admin` = личка админа); не фатально, фейл только варнит |
| `-g` | Тегнуть сборку в git (`-n` + датавремя); на грязном дереве отказывается |
| `-D` | С `--push`: ченджлог между предыдущим тегом и свежим (текст или `changes_<tag>.txt`) |
| `--diff-from TAG` | С `--push`: принудительный ченджлог `TAG..HEAD` (перебивает `-D`) |
| `-T TEXT` | С `--push`: приписка к сообщению с zip |
| `--no-patches` | Пропустить микро-патчи мейнтейнера (для тестовых сборок на перецелевых снапшотах) |

Удалены: `-k/--kernel`, `--force` (нет kernel-профилей - стоковое ядро сохраняется) - отклоняются с ошибкой (`build.sh:270-273`); `-c/--cpio-only`, `--platform-recovery`, `-N/--no-first-stage` (теперь всегда включены) - принимаются как no-op с NOTE (`build.sh:274-277`).

</details>

<details>
<summary>🏭 Что происходит (5 стадий)</summary>

1. **Цель.** Фиксирована: `DEVICE_BUILD_FLAG=aio` (не-`aio` в `-f` - ошибка). Список устройств покрывает каждый `devices/*/device.conf`.
2. **Стоковое ядро.** Образ ядра не собирается, cmdline не компонуется: в `BoardConfig.mk` только dummy-`VENDOR_CMDLINE` для промежуточного `vendor_boot` (он отдаёт platform-фрагмент).
3. **Env-файл.** `vendorsetup.sh` (lunch) пишет `.build_platform.conf` (aio-платформа, оба KeyMint HAL, уровень LGZ, ключи раскладки): env не переживает ninja recipe-shell'ы, поэтому параметры едут файлом. Перед сборкой обновляется снапшот `/tmp/pixels/fox_env.sh` - post-image хук вызывается с зачищенным окружением, и без файла терялись `FOX_BUILD_TYPE`/`OUT`.
4. **Soong.** `recovery_init_stub`, `recovery-tensor-daemon`, `recovery-pixel-boot` и **оба** KeyMint HAL собираются **из исходников**. Оверлеи: `TARGET_RECOVERY_DEVICE_DIRS` = корень + каждый `devices/*` + каждый `families/*` - один универсальный cpio.
5. **Колбэк (`--second-call`).** `fox_build_callback.sh` на готовом рамдиске: оба KeyMint HAL + VINTF-фрагменты всех семей, заглушка `twrp.flags` + swap-kit (`twrp.flags.<fam>` / `recovery.fstab.<fam>` / `recovery.wipe.<fam>` / `families.txt`), мердж `pixelrunatboot.json` (`[PIXELCFG]`), зануление USB в UNKNOWN, `post_remove_ramdisk`, LGZ-пакование (`[LGZ]`), снапшот-манифест и reflash-списки.

</details>

<details>
<summary>📦 Что выдаёт сборка</summary>

- Один универсальный пейлоад вместо посемейных образов. Стоковое ядро сохраняется, точный девайс определяется в рантайме, семейные файлы (`recovery.fstab`, `twrp.flags`, USB-контроллер, KeyMint) подменяются init-стабом + boot-движком.
- Выход: `builds/OrangeFox-R12.0-test8-aio.zip` - автономный установщик (оба слота, бэкап userdata) + пейлоад `*.ramdisk.lz4` (platform-фрагмент, `fastboot flash vendor_boot:`). Push/test-флаги (`--push`, `-g`, `-D`, `-T`) работают на этом единственном маршруте.

</details>

## Типы сборки: Stable vs Beta

| | `Stable` (дефолт, точное совпадение) | Любой другой (`Beta`, …) |
|---|---|---|
| `OF_ADVANCED_SECURITY` | `1` | `0` |
| `adbd` в рекавери | остановлен при загрузке, adb мёртв by design | жив, root |
| MTP | автостарт выкл | автостарт вкл |

Следствие: на Stable пароль расшифровки вводится **только с экрана**; adb-для-пароля работает только на не-Stable сборках. Тестерам - `--build-type Beta`.
